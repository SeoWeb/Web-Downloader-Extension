## Context

The localization system serves 45 locales via JSON files under `src/i18n/locales/`. A recent branch added two sets of keys to `en.json` but did not fully propagate them:
1. `filter.alwaysAskWhereToSave` — added with English text as placeholder in all 44 non-English files
2. 9 download-interruption keys under `status.*` — missing entirely from all 44 non-English files

The existing localization spec already requires that non-English files contain translated values (not English) for every key in `en.json`.

## Goals / Non-Goals

**Goals:**
- Ensure `filter.alwaysAskWhereToSave` has a proper translation in all 44 non-English locale files
- Add the 9 missing download-interruption keys with proper translations to all 44 non-English locale files
- Preserve all existing interpolation placeholders (e.g., `{{phase}}`)

**Non-Goals:**
- Reviewing or fixing existing translations that may be inaccurate
- Adding new locales or changing the i18n infrastructure
- Modifying any code outside of locale JSON files

## Decisions

**Decision: AI-generated translations**
All translations will be generated by the LLM. This is a pragmatic choice for a browser extension with many locales — the strings are simple UI labels and error messages. Any inaccurate translations can be corrected by contributors later.

**Decision: Single bulk update per file**
Each locale file will receive both the `alwaysAskWhereToSave` fix and the 9 missing keys in one edit, minimizing review noise.

## Risks / Trade-offs

- [AI translation accuracy] → The strings are short, context-free UI labels. Risk of bad translations is low. Community corrections are welcome via PRs.
- [Brand names in extraction keys] → The `extraction.*` keys (Windows, macOS, 7-Zip, etc.) also match English text but are brand/proper names that are universal — these are intentionally left unchanged.
